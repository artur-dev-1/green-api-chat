# GREEN-API Chat

Веб-интерфейс для отправки и получения текстовых сообщений в WhatsApp через [GREEN-API](https://green-api.com). Внешний вид повторяет тёмную тему веб-версии MAX ([web.max.ru](https://web.max.ru/)).

**Демо:** https://artur-dev-1.github.io/green-api-chat/

> Задание предполагало мессенджер MAX. Авторизовать инстанс MAX не удалось: мобильного приложения MAX нет в App Store моего региона, а без него QR-код не отсканировать. Поэтому, как разрешено в задании, чат сделан для WhatsApp. API у GREEN-API для обоих мессенджеров устроен одинаково, так что переход на MAX сводится к формату `chatId` и методу проверки номера.

## Возможности

- Вход по `apiUrl`, `idInstance` и `apiTokenInstance` из личного кабинета GREEN-API. Креды проверяются методом `getStateInstance`.
- Создание чата по номеру телефона. Перед созданием номер проверяется методом `checkWhatsapp`.
- Отправка текстовых сообщений методом [`sendMessage`](https://green-api.com/docs/api/sending/SendMessage/).
- Получение сообщений через [HTTP API](https://green-api.com/docs/api/receiving/technology-http-api/): `receiveNotification` + `deleteNotification`.
- Сообщения, отправленные с телефона, тоже попадают в чат. Если приходит сообщение от нового контакта, чат с ним создаётся автоматически.
- Статусы сообщений: отправляется, отправлено, не отправлено (с повторной отправкой). Если в инстансе включены уведомления о статусах, показываются ещё «доставлено» и «прочитано».
- История чатов хранится в `localStorage` отдельно для каждого инстанса.
- Адаптивная вёрстка: на мобильных устройствах одновременно виден либо список чатов, либо открытый чат.

## Стек

React 19, TypeScript, Vite, SCSS Modules. Сторонних библиотек нет: задание просит максимально простой интерфейс.

## Локальный запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
git clone https://github.com/artur-dev-1/green-api-chat.git
cd green-api-chat
npm install
npm run dev
```

Приложение откроется на http://localhost:5173.

Другие команды:

```bash
npm run build    # production-сборка в dist/
npm run preview  # просмотр production-сборки
npm run lint     # oxlint
```

При пуше в `main` проект автоматически собирается и публикуется на GitHub Pages (`.github/workflows/deploy.yml`).

## Подготовка инстанса GREEN-API

1. Зарегистрируйтесь в [личном кабинете](https://console.green-api.com) и создайте инстанс (подойдёт бесплатный тариф Developer).
2. Авторизуйте инстанс: нажмите «Получить QR» и отсканируйте код в WhatsApp (Настройки → Связанные устройства → Привязка устройства).
3. В настройках инстанса:
   - оставьте **Webhook URL пустым**, иначе уведомления уйдут на вебхук, а не в очередь HTTP API;
   - включите получение уведомлений о входящих сообщениях;
   - при желании включите уведомления об исходящих сообщениях, чтобы видеть в чате сообщения, отправленные с телефона.
4. Скопируйте `apiUrl`, `idInstance` и `apiTokenInstance` и введите их на странице входа.

## Как это работает

```
src/
├── api/greenApi.ts            # запросы к GREEN-API и типы уведомлений
├── hooks/
│   ├── useChatStore.ts        # состояние чатов (useReducer) + сохранение в localStorage
│   └── useNotifications.ts    # цикл long polling очереди уведомлений
├── lib/
│   ├── notifications.ts       # уведомление GREEN-API → действие для store
│   ├── phone.ts               # нормализация номера и chatId
│   ├── format.ts              # даты и время
│   └── storage.ts             # безопасная работа с localStorage
├── components/
│   ├── LoginScreen/           # вход по данным инстанса
│   ├── Messenger/             # связывает store, polling и отправку
│   ├── Sidebar/               # список чатов и создание нового чата
│   ├── ChatWindow/            # лента сообщений и поле ввода
│   └── Avatar/
└── styles/                    # глобальные токены и SCSS-миксины
```

**Получение сообщений.** `useNotifications` запускает цикл: `receiveNotification` с `receiveTimeout=20`, то есть сервер держит запрос до 20 секунд, пока очередь пуста. Затем уведомление обрабатывается и удаляется через `deleteNotification`, чтобы не прийти повторно. При ошибке цикл ждёт 5 секунд и продолжает, а в шапке списка чатов показывается ошибка. При выходе или смене инстанса цикл останавливается через `AbortController`.

**Отправка.** Сообщение сразу появляется в ленте со статусом «отправляется» и временным id. После ответа `sendMessage` временный id заменяется на `idMessage`. Уведомление `outgoingAPIMessageReceived` о том же сообщении может прийти раньше ответа API. Тогда reducer находит ожидающее сообщение с тем же текстом и подтверждает его, а не добавляет дубль.

**Состояние.** Хватает одного `useReducer` без внешних библиотек: все изменения идут через `chatReducer`, поэтому логику дедупликации и счётчиков непрочитанных легко проследить в одном месте.

## Ограничения

- Поддерживаются только текстовые сообщения (`textMessage` и `extendedTextMessage`), остальные типы игнорируются.
- История хранится только в браузере. Сообщения, пришедшие до первого входа, не загружаются.
- Креды сохраняются в `localStorage`, чтобы не вводить их после перезагрузки. В реальном продукте токен лучше держать на бэкенде.
- Если открыть приложение в нескольких вкладках с одним инстансом, они будут делить одну очередь уведомлений, и каждое сообщение получит только одна вкладка.
